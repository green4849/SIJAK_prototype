## 다시 정한 작업 순서

### 0. 현재 첫 이용 경로 검증과 막힘 해소

1. #91의 CI·병합·운영 반영을 확인하고, 잠든 서버에서 첫 화면이 스스로 회복되는지 실제 브라우저에서 확인한다. #91의 다른 작업자와 코드를 중복 수정하지 않는다.
2. 동네 위치 조회가 느리거나 권한이 거부됐을 때도 가입할 수 있도록 동네 수준의 수동 선택 경로를 설계·구현한다. 저장 정보는 현재와 같이 대략적인 지역으로 제한한다.
3. 실제 카카오 계정으로 1~6단계를 한 번 끝까지 확인한다. 특히 5번 세 선택지와 신청 시 포인트, 6번 건너뛰기를 확인한다. 로그인 없는 시연 화면 검증과 구분해 기록한다.

### 1. 운영 약속을 지킬 수 있는 기반

1. 탈퇴 30일·음성 90일 삭제 예약 작업과 암호화 백업을 활성화하고 복구를 검증한다. 운영 DB 접속은 현재 사용자 정책상 중지돼 있으므로, 이 단계는 별도 명시적 요청 전까지 로컬 코드·절차 검토와 필요한 값 목록 정리에 한정한다.
2. 임시 디스크에 저장되는 음성 파일을 영속 저장소로 옮긴다. 이후 음성 파일 삭제 작업도 같은 저장소를 대상으로 검증한다.
3. VAPID 키·실기기 Web Push, 긴급 문자 공급자, Sentry를 각기 설정·검증한다. 코드 완료와 운영 발송 성공을 별도 상태로 기록한다.
4. 약관의 운영자 정보·법률 검토, 위치정보 의무, 60세 이상 기준을 결정한다. 카카오 로그인은 본인확인이 아니며 Firebase·PASS는 현재 운영 경로에 넣지 않는다.

### 2. 대화와 접근성

1. A5 받아쓰기: 지원 브라우저의 글 입력칸에 버튼을 두고, 인식 결과를 입력칸에 채워 확인 후 전송한다. 미지원 기기에는 버튼을 숨긴다. 서버 STT가 없는 기기의 음성 메시지와 구분한다.
2. C1 실시간 대화: WebSocket을 추가하되 끊기면 기존 3초 폴링으로 돌아간다.
3. C2 음성 메시지 자막·서버 STT: 엔진과 보관·전송 정책을 정하고, 실제 어르신 발화의 오류율을 측정한다. 자막이 생긴 뒤 음성 메시지에도 위험 탐지를 연결한다. 브라우저 TTS(A6)는 이미 구현된 범위다.
4. D4 주요 폼·훅 시험과 D5 핵심 화면 시각 회귀를 보강한다.

### 3. AI와 돌봄 판단

1. C8 말동무 백엔드: 텍스트 대화·저장·위기 및 의료 응답 경계를 먼저 구현하고, 제공자·비용·개인정보 처리·평가 기준을 정한다. 현재 말동무 화면은 시연 응답이다.
2. C14 시작이 실제 AI: 기존 기기 내 안내를 안전한 기본값으로 두고, 화면 맥락·버튼 안내 계약에 서버 응답을 연결한다.
3. C6 위험 탐지 고도화와 C11 마음 상태 위험 단계 알림: 오탐·누락 평가, 보호자·복지사에게 알려도 되는 조건과 동의 흐름을 확정한 뒤 구현한다.
4. 운영자 경고 문구 발송과 지역별 담당 범위를 추가한다.

### 4. 추가 기능과 현장 검증

1. A9 선택형 프로필 사진은 영속 저장소·형식·크기·개인정보 제거 규칙을 정한 뒤 구현한다.
2. C12 포인트 충전·결제와 봉사 참석 확인은 결제사·복지기관 운영 절차가 정해진 뒤 연결한다.
3. C9 음성 통화는 연결 방식과 신고·차단·녹음 정책을 정한 뒤 구현한다. 현재는 통화 기능이 없다.
4. A11 실제 어르신·실기기 사용성 평가로 가입, 친구 신청, 대화, 긴급 도움의 이해도와 접근성을 확인한다. 시연 자동 시험은 실제 사용자 평가를 대신하지 않는다.
