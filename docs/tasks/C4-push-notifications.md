## 설계 — Web Push (2026-11-27)

### 왜 Web Push 인가
- 앱이 PWA(웹)라 브라우저 표준 Web Push 로 앱스토어 없이 보낼 수 있다. FCM·APNs 계정이 따로 필요 없다 — 서버 키(VAPID) 한 쌍만 있으면 된다
- 받는 곳: 안드로이드 크롬·삼성 인터넷(설치 안 해도), PC 크롬·엣지·파이어폭스, **아이폰은 iOS 16.4+ 에서 '홈 화면에 추가'한 앱만**. 그래서 화면이 아이폰 사파리에서는 '홈 화면에 추가하면 받을 수 있어요'로 안내한다
- 알림함(앱 안 목록)이 기준이고 푸시는 '앱 밖으로 알리는 통로'다. 푸시를 못 받거나 꺼도 소식은 알림함에 그대로 남는다

### 무엇을 보내나
| 일 | 받는 사람 | 알림 문구 | 알림함 |
|---|---|---|---|
| 친구 신청 받음 | 받은 사람 | 새 친구 신청 · ○○님이 친구 신청을 보냈어요 | O |
| 친구가 됨 | 상대 | 친구가 되었어요 · … | O |
| 위험 대화(경고 이상) | 받은 사람 | 조심하세요 · ○○님 메시지에 … 있어요 | O |
| 마음 건강 다시 살필 때 | 본인 | 마음 건강 살펴볼 때예요 | O |
| **새 메시지** | 받은 사람 | ○○님이 메시지를 보냈어요 · 눌러서 확인해 보세요 | X (대화 목록이 곧 알림함) |
| 활동 신청 | 본인 | 보내지 않음 — 방금 스스로 한 일 | O |

- **메시지 내용은 알림에 넣지 않는다.** 잠금 화면에 대화가 보이지 않게, 위험 대화 문구가 그대로 퍼지지 않게. 같은 대화방 알림은 `tag` 로 하나로 합쳐 여러 개가 쌓이지 않는다
- 위험 대화(경고 이상)인 메시지는 '조심하세요' 알림 하나만 보낸다(새 메시지 알림을 따로 보내지 않음)
- 밤 9시~아침 8시(한국 시각)에는 **소리·진동 없이**(`silent`) 보낸다. 미루려면 예약 작업이 필요한데 무료 플랜에는 없어서, 버리지 않고 조용히 보낸다

### 흐름
```
친구 신청 등 ─ NotificationService.on_*() ─ 알림함 줄 추가(커밋 전) + 그 사람의 구독 목록을 읽어 '보낼 것'으로 세션에 담음
                                              │ 부른 쪽이 commit
                                              ▼  (rollback 이면 버림 — 저장 안 된 소식은 알리지 않는다)
                       after_commit → 백그라운드로 Web Push 발송 (pywebpush, 스레드에서)
                                              │ 404·410 = 구독 만료 → 그 구독 삭제
```
- 발송은 요청 응답을 붙잡지 않는다(백그라운드). 실패해도 요청·알림함에는 영향 없음. 재시도는 하지 않는다(알림함이 남아 있음)
- 서버 키가 없으면(기본) 발송기가 꺼져 있고, 화면도 '켜기' 대신 '아직 준비 중'으로 보인다 — 문자(SMS)·S3 와 같은 규칙

### 데이터
`push_subscriptions` — 기기(브라우저) 하나에 한 줄
- `endpoint`(유니크) · `p256dh` · `auth` · `user_id`(탈퇴하면 함께 삭제) · `created_at` · `last_sent_at`
- 같은 기기에서 다른 계정으로 로그인해 켜면 그 계정으로 옮겨진다(endpoint 유니크) — 앞 사람 알림이 뒷사람에게 가지 않게
- 로그아웃하면 화면이 이 기기 구독을 먼저 지운다

### API (`/api/v1/notifications/push…`)
| | |
|---|---|
| `GET /notifications/push` | `{enabled, public_key}` — 서버가 보낼 수 있는지, 구독에 쓸 공개 키 |
| `PUT /notifications/push/subscription` | 이 기기 구독 등록·갱신 `{endpoint, keys:{p256dh, auth}}` |
| `POST /notifications/push/unsubscribe` | 이 기기 구독 삭제 `{endpoint}` (내 것만) |
| `POST /notifications/push/test` | 내 기기들로 시험 알림 한 통 `{sent, failed}` |

- **보안**: 서버가 이 주소로 요청을 보내므로 아무 주소나 받지 않는다 — `https` + 알려진 푸시 서비스 호스트만(구글 FCM·모질라·애플·마이크로소프트). 사내망·임의 주소로 요청을 보내게 하는 공격(SSRF) 방지
- 기기는 한 사람당 10대까지(오래된 것부터 정리)

### 서버 설정 (Render 환경값)
| 이름 | 값 |
|---|---|
| `VAPID_PUBLIC_KEY` | 공개 키 (화면에 내려감 — 비밀 아님) |
| `VAPID_PRIVATE_KEY` | 비밀 키 — Render 화면에만. 잃으면 새로 만들고 모두 다시 구독 |
| `VAPID_SUBJECT` | 연락처 `mailto:…` 또는 사이트 주소 (푸시 서비스가 문제 있을 때 연락) |

키 만들기: `cd backend && uv run python -m scripts.vapid_keys` → 출력된 두 값을 Render 에 넣고 다시 배포 (docs/deploy-render.md '휴대폰 알림 켜기')

### 화면
- 설정 → 알림 칸 맨 위 **'휴대폰 알림'** 카드: 꺼짐이면 [알림 켜기] → 브라우저 허용 창 → 켜짐 + [시험 알림 보내기]
- 상태별 안내: 이 브라우저는 못 받음 / 아이폰은 홈 화면에 추가 필요 / 허용을 거절함(브라우저 설정에서 다시 허용하는 법) / 서버 준비 중
- 설정을 열 때 이 기기가 켜져 있으면 구독을 서버에 다시 알린다 — 만료 정리·다른 계정 로그인 뒤에도 맞게
- 서비스 워커(`sw.js`): `push` → 알림 표시, 알림을 누르면 열린 앱 창으로 그 화면(`link`)을 열거나 새로 연다
- 시연(데모) 모드는 보낼 서버가 없어 '준비 중' 안내가 보인다
- 로그아웃하면 이 기기 구독을 먼저 지운다(`shared/lib/push.unsubscribeDevice`)
