# B2. 요청 횟수 제한

| 영역 | 크기 | 우선 | 상태 | 브랜치 |
|---|---|---|---|---|
| 실서비스 필수 | M | P0 | ✅ 완료 | `prod/B2-rate-limit` |

## 왜
인증번호 무차별 대입, 메시지·신고 스팸.

## 손댈 곳
`backend/app/core/ratelimit.py` + 각 도메인 router (저장소는 메모리 → Redis는 B9)

## 완료 기준
- [x] 인증번호 요청: 번호당·IP당 제한
- [x] 메시지: 사용자당 분당 제한
- [x] 초과 시 429 + 어르신이 이해할 문구

## 진행 기록

- slowapi 대신 직접 작은 모듈(`core/ratelimit.py`): `Rule(name, limit, window_sec, action)` + `enforce(rule, key)`. 미끄러지는 창 방식, 거절된 시도는 기록하지 않음(기다리는 시간이 계속 늘지 않게)
- 저장은 `RateLimitStore` 인터페이스 뒤 `MemoryRateLimitStore`(서버 1대 기준). **여러 대로 늘리면 Redis 구현으로 교체 → B9** (호출 코드는 그대로)
- 규칙은 각 router가 소유:
  | 대상 | 기준 | 한도 |
  |---|---|---|
  | 인증번호 요청 | 전화번호 / IP | 10분 5회 / 10분 20회 |
  | 인증번호 확인 | IP | 10분 30회 (세션당 5회 오답 제한은 Mock PASS에 이미 있음) |
  | 메시지 | 사용자 | 1분 20회 (음성 10회) |
  | 친구 신청 | 사용자 | 1시간 30회 |
  | 신고 | 사용자 | 1시간 10회 (차단은 제한 없음 — 위험할 때 바로) |
- 초과 시 429 `rate_limited` + `Retry-After` + "인증번호 요청을 너무 여러 번 했어요. 9분 뒤에 다시 해 주세요." (받침에 따라 을/를). 프론트는 서버 문구를 그대로 보여 줌
- IP는 `request.client.host` — 프록시 뒤에서는 uvicorn `--proxy-headers` 설정 필요 (B10 배포 문서에)
- `RATE_LIMIT_ENABLED` 설정(기본 켬). 테스트는 매번 기록 비움
- 테스트: 단위 5개(창·키 분리·문구), 통합 2개(번호별 인증 요청, 사용자별 메시지)
