# C12. 포인트·추천 평가·대화 주제·봉사모임

| 영역 | 크기 | 우선 | 상태 | 브랜치 |
|---|---|---|---|---|
| 기능 확장 | L | P1 | 🔨 PR 리뷰 대기 | `feat/C12-points-engagement` |

## 왜
캡스톤 기획 회의(2026-10-13)에서 나온 수익 구조·참여 장치를 프로토타입에 넣는다.

- 추천 친구를 평가하면 추천에 반영하고 포인트를 준다 → 추천 품질 데이터 + 재방문
- 친구 신청(=대화 시작)에 포인트를 쓰게 해서 무분별한 신청을 줄이고, 포인트 충전·구독을 수익 모델로
- 봉사활동(복지관 연계) 참여·첫 친구 사귀기로도 포인트를 벌 수 있게 → "돈 내야 친구 사귄다"는 인상 완화
- 대화 첫마디가 어려운 어르신을 위해 공통 관심사 기반 대화 주제 추천

## 결정 사항 (회의 원안 → 프로토타입)

| 원안 | 프로토타입 | 이유 |
|---|---|---|
| 하루 3~4번 추천 푸시 | 하루 1·2번·받지 않기 중 선택 + 받는 시간, 밤 9시~아침 8시 금지 (설정만, 발송은 C4) | 알림 피로 → 알림을 못 끄는 어르신은 앱을 지운다 |
| 별점 | 3단계 (만나보고 싶어요 / 그저 그래요 / 잘 안 맞아요) | 별 5개는 고르기 어렵다. 추천에 쓰기엔 3단계로 충분 |
| 평가마다 포인트 | +10P, **하루 5번까지** | 아무거나 눌러 포인트만 받는 것 방지 |
| 대화 신청·호감에 포인트 | **친구 신청**에 30P (첫 신청 무료, 받은 신청 수락은 늘 무료) | 앱에서는 친구가 되어야 대화 가능 → 친구 신청 = 대화 신청 |
| 무료 대화 5회 → 구독 | 포인트 하나로 통일, 구독 = 매달 포인트 (화면만, 결제는 범위 밖) | 과금 축을 하나로 |
| 체험단 기간 전부 무료 | `POINT_FREE_UNTIL` 설정 날짜까지 차감 없음 | |
| 첫 친구 3명 → 포인트 | **대화를 서로 한 번 이상 나눈 친구** 3명 → +500P | 아무나 추가해서 받는 것 방지 |
| 대화 주제·자동 메시지 | 공통 관심사 기반 추천 문구 (지금은 규칙, LLM 자리만). 누르면 입력칸에 들어가고 보내기는 직접 | 자동 전송은 하지 않는다 |
| 봉사활동 모임 | 지역생활에 '봉사' 분류, 신청 시 +100P (취소하면 회수) | 원래는 복지관 참석 확인 후 지급 → deferred §6 |

## 진행 기록

- **포인트 원장**(`point_entries`): 잔액 테이블 없이 합계로. `UNIQUE(user_id, ref)`로 더블 탭·재시도에도 한 번만 적립·차감. 잔액 확인~차감은 사용자 단위 advisory lock. 포인트 서비스는 커밋하지 않아 친구 신청·봉사 신청과 한 트랜잭션 — 모자라면(402 `insufficient_points`) 신청도 저장되지 않음
- **금액은 서버 한 곳**(`point/service.py`): 가입 100 · 평가 10(하루 5번) · 봉사 100 · 첫 친구 미션 500 · 친구 신청 30. 화면은 `GET /points` 값으로 문구를 만든다 — 바꿀 때 프론트 수정 없음 (데모 사본은 `demo/constants.ts`)
- **평가 반영**: 추천 탭에서 만나보고 싶어요 → 미평가 → 그저 그래요 순, 잘 안 맞아요는 제외(같은 동네 탭은 거리 목록이라 그대로). '만나보고 싶어요' 받은 이웃들의 관심사를 가진 사람에게 가산점 0.5
- **첫 친구 미션**: 테이블 없이 대화 기록으로 계산(`mission` 도메인 → chat·point 서비스). 서로 한 번 이상 말한 친구만
- **대화 주제**: 관심사별 문구 2개씩(어르신 말투, 질문형) — 공통 관심사 → 상대 관심사 → 일상. 첫마디 전엔 펼쳐 두고, 고르면 입력칸에만(자동 전송 없음). 입력줄이 높아지면 목록 아래 여백도 같이(ResizeObserver)
- **feature 경계**: friend·activity는 points를 모른다 → `onPointsChanged`·`onInsufficientPoints`·`requestPrice` 를 페이지가 넘김. chat 의 `ChatService` 의존성은 mission이 쓰도록 `chat/deps.py` 로 이동
- **데모**: 시드 VERSION 4 — 김시작 110P(유료 신청 3번 뒤 4번째에 부족 안내), 봉사 활동 2개. 체험 기간은 데모에서 끔(포인트 흐름이 보이게)
- 테스트: 백엔드 통합 10 + 단위 3(대화 주제), e2e 7(`points.spec.ts`), 접근성 스윕에 `/me/points`·`/me/notifications`·봉사 탭 추가 — 기본/아주 크게+선명/320px 모두 통과
- 별건 발견: `scripts/seed.py` 의 윤기철 소개글이 60자 제한을 넘어 main에서도 사용자 시드가 실패함(이 PR에서는 손대지 않음)
