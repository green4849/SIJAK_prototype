# A4. 동작 후 피드백 — 토스트·진동

| 영역 | 크기 | 우선 | 상태 | 브랜치 |
|---|---|---|---|---|
| 폴리싱 | S | P1 | ✅ 완료 | `polish/A4-action-feedback` |

## 왜
보고서 UI 원칙 '직접적 피드백'. 지금은 저장·신청·수락 후 화면만 바뀌어 성공했는지 알기 어렵다.

## 손댈 곳
shared/ui/Toast (신설), 주요 동작(프로필 저장·친구 신청/수락·활동 신청/취소·신고·차단)

## 완료 기준
- [x] 큰 글씨 토스트가 화면 아래에 3~4초, 화면 낭독기도 읽음(role=status)
- [x] 지원 기기에서 짧은 진동 (설정에서 끌 수 있음)
- [x] 같은 토스트가 쌓이지 않음
- [x] e2e에서 토스트 확인

## 진행 기록

- `shared/lib/toast.ts` (상태·`toast(message, tone)`) + `shared/ui/Toast.tsx` ToastHost(App에 1개). 저장소와 컴포넌트를 나눈 이유: 한 파일에 섞으면 fast-refresh 규칙(only-export-components) 위반
- 한 번에 하나만 표시: 새 토스트가 이전 것을 바꿔치기, 같은 문구면 시간만 연장. 4초 뒤 자동으로 닫히고, 누르면 바로 닫힘
- 낭독: 항상 있는 `role=status` 영역 안에 내용이 바뀌어 읽힘. 버튼 이름은 "… (누르면 닫혀요)"
- 위치: 하단 고정 막대(`data-bottom-bar`: 하단 탭·대화 입력줄·활동 신청 영역)의 높이를 ResizeObserver로 재서 그 위에 띄움 — 처음엔 탭 높이로 고정했더니 활동 상세의 '신청했어요' 문구를 가렸음
- 진동: 성공 40ms, 오류 짧게 두 번. 설정(마이페이지 › 설정) '진동' 끄기 가능, 기본 켜짐
- 연결한 동작: 친구 신청/수락/거절, 활동 신청/취소/관심, 신고·차단·차단 해제, 위치 저장, 프로필 저장
- e2e `feedback.spec.ts`: 토스트 문구·1개 유지·누르면 닫힘·4초 뒤 사라짐·하단 막대 안 가림·진동 횟수·진동 끄기
