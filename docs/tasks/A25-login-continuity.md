# A25. 시작 → 본인 확인, 이어지는 화면

| 영역 | 크기 | 우선 | 상태 | 브랜치 |
|---|---|---|---|---|
| 폴리싱 | S | P1 | ✅ | `polish/login-continuity` |

> 앞 작업: A22 시작 화면 다듬기의 '이번에 하지 않은 것'

## 왜
시작 화면(①)에서 '시작하기'를 누르면 로그인·본인인증 방법 선택 화면(②)으로 화면이 통째로 바뀌었다. 두 화면이 따로 노는 느낌이었고, ② 화면 제목 「안녕하세요 시작입니다」는 이 화면에서 무엇을 하는지 말해 주지 않았다.

## 바뀐 것 (사용자 관점)

### 1. 새싹이 다음 화면으로 날아가 붙는다
- '시작하기'를 누르면 시작 화면 가운데의 큰 새싹이 작아지면서 ② 화면 위쪽 '시작' 로고 자리로 이동하고, 나머지 내용은 짧게 엇갈려 바뀐다(약 0.6초).
- 화면이 '바뀌는' 게 아니라 '이어지는' 느낌 — 같은 앱 안에서 다음 단계로 들어간다는 감각을 준다.
- 지원하지 않는 브라우저(일부 오래된 사파리 등)에서는 예전처럼 그냥 넘어간다. 기기에서 '움직임 줄이기'를 켰으면 전환 없이 바로 넘어간다.

### 2. ② 화면 머리를 '이 화면에서 할 일'로
- 위쪽에 작은 새싹 + '시작' 로고(새싹이 날아와 붙는 자리).
- 제목: 「안녕하세요 시작입니다」 → **「본인 확인을 할게요」** — 이 화면에서 할 일을 바로 말한다.
- 그 아래 한 줄: **「실명이 확인된 우리 동네 이웃만 만나요.」** — 왜 본인 확인을 하는지, 서비스의 안심 포인트를 첫 단계에서 알린다.
- 휴대폰 인증 · 신분증 인증 · 도움받기 세 가지 선택은 그대로.

## 완료 기준
- [x] 시작하기 → ② 이동 시 새싹 전환 동작 (지원 브라우저), 미지원·움직임 줄이기에선 바로 이동
- [x] ② 화면 머리: 로고 · 제목 · 한 줄 안내
- [x] typecheck·lint·build, CI e2e

## 진행 기록
- 움직이는 시안에서 먼저 보여 준 '다음 화면' 모습(머리에 새싹 로고, 큰 제목, 한 줄 안내)을 실제 ② 화면에 반영
- 전환은 브라우저의 화면 전환 기능(View Transitions)을 쓴다 — 새싹 두 개(① 큰 새싹, ② 작은 로고)를 같은 이름으로 묶어 브라우저가 위치·크기를 이어 준다
- 뒤로(② → ①)는 전환 없이 돌아가고, 시작 화면 등장 연출이 다시 나온다
