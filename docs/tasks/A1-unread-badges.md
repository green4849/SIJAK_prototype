# A1. 하단 탭·홈 카드에 안 읽은 메시지·받은 친구 신청 배지

| 영역 | 크기 | 우선 | 상태 | 브랜치 |
|---|---|---|---|---|
| 폴리싱 | S | P1 | ✅ 완료 | `polish/A1-unread-badges` |

## 왜
새 메시지·친구 신청이 와도 해당 화면에 들어가야만 알 수 있다.

## 손댈 곳
app/BottomNav, pages/HomePage, features/chat·friend 개수 훅, shared/ui/Badge

## 완료 기준
- [x] 홈 '대화하기' 카드에 안 읽은 메시지 수, '친구 찾기' 카드·친구 탭에 받은 신청 수
- [x] 화면 낭독기가 '친구, 새 친구 신청 1개'처럼 읽는다 (숫자만 읽히지 않게)
- [x] 폴링은 화면 수와 관계없이 한 번만 (같은 데이터를 여러 곳에서 써도 요청 중복 없음)
- [x] 대화방을 읽고 나오면 배지가 바로 줄어든다
- [x] 99개 초과는 99+
- [x] e2e 추가

## 진행 기록

- `shared/lib/createPolledStore`: 구독자가 몇이든 요청 1개, 화면 숨김 시 건너뜀, `refresh()`로 즉시 갱신
- chat `useUnreadTotal`(15초, 차단 대화 제외) · friend `useReceivedCount`(30초) — 대화방 열고/나갈 때, 신청 수락·맞신청 시 즉시 갱신
- 대화는 탭이 없어 **홈 탭 + '대화하기' 카드**에 표시, 친구 신청은 **친구 탭 + '친구 찾기' 카드**
- `shared/ui/Badge` part=dot/text: 아이콘 위 숫자와 낭독 문장을 분리 — 처음엔 탭에서 "안 읽은 메시지 1개 홈" 순서로 읽히던 것을 e2e가 잡아 수정
- e2e `badges.spec.ts`: 낭독 순서, 읽음/수락 후 즉시 사라짐, 4곳에서 써도 요청 1번(데모 호출 수 집계)
