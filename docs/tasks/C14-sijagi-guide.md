# C14. 시작이 앱 가이드

| 영역 | 크기 | 우선 | 상태 | 브랜치 |
|---|---|---|---|---|
| 기능 확장 | M | P1 | 🎭 화면·기기 안 답변 완료 / 실제 AI 대기 | `feat/C14-sijagi-guide` |

## 왜

60~80대 사용자가 앱에서 막혔을 때, 곁에 있는 안내자에게 평소 말하듯 묻고 **지금 보고 있는 화면을 기준으로** 다음 행동을 이해해서 **직접 해 볼 수 있게** 한다. 도움말 목록에 캐릭터를 붙이는 것이 목적이 아니다.

처음 구현(PR #30)은 이 의도에 못 미쳤다.

| 처음 구현 | 문제 |
|---|---|
| 화면을 어둡게 덮는 창(Sheet) | 묻고 있는 화면이 가려져 "이 화면에서 뭘 해야 해?"를 화면을 보며 물을 수 없다 |
| 글자가 가장 길게 겹치는 키워드 하나 고르기 | 띄어쓰기·말투가 조금만 달라도 못 알아듣고, 어느 화면에서 물었는지 보지 않는다 |
| 답 + '그 화면으로 가기' 링크 | 버튼이 어디 있는지는 알려 주지 못한다. 다음에 혼자 하는 법이 남지 않는다 |
| 대화·말동무 화면에서는 버튼을 숨김 | 가장 막히기 쉬운 곳(보내기, 신고)에서 물을 수 없다 |
| 가입 전에는 질문 2개만 | "글씨를 키우고 싶어"에 "로그인한 뒤 설정에서"라고 답한다 |
| '묻기' 뒤 답이 나옴 | 무엇이 답하는지 밝히지 않아 AI나 상담원처럼 보일 수 있다 |

## 역할 나누기

| | 무엇을 | 어떻게 |
|---|---|---|
| **시작이** (이 작업) | 앱 사용법 — 어디를 눌러야 하는지 | 묻는 화면을 보고 답하고, 버튼을 짚어 준다 |
| **말동무** (C8) | 일상 이야기, 정서 지지 | 대화. 시작이는 "이야기는 말동무가 들어 드려요"라고 넘긴다 |
| **도움말** (`/me/help`) | 자주 묻는 질문 | 읽는 목록. 목록에 없으면 시작이를 부르는 버튼이 있다 |

"심심해", "외로워"처럼 이야기를 원하는 말에는 사용법을 늘어놓지 않고 말동무 위치를 알려 준다. 반대로 말동무 화면에서 "‘말하기’가 어디 있어?"는 시작이가 답한다.

## 이번에 한 것

### 1. 시작이가 직접 나온다 — 창이 아니라 캐릭터

처음에는 ‘물어보기’ 글자가 달린 버튼과 "시작이에게 물어보기"라는 제목의 창이었다. 도움 창에 얼굴 아이콘을 붙인 모양이라, **시작이가 화면 위를 옮겨 다니며 직접 말하고 가리키는** 구조로 바꿨다.

| 장면 | 시작이 |
|---|---|
| 평소 | 오른쪽 아래 구석에 시작이만 서 있다 (상자·글자 없음). 시작이가 곧 버튼이다 |
| 처음 온 화면 | 손을 흔들며 먼저 한마디 건넨다 ("친구를 찾는 곳이에요. 도와드릴까요?") |
| 누르면 | 앞으로 나와 말풍선 왼쪽 위에 올라서서 말한다. 말풍선이 곧 창이다 (제목 없음) |
| 답할 때 | 답의 성격에 따라 표정·몸짓이 바뀐다: 인사 / 기쁨 / 생각(되묻거나 모를 때) / 걱정(위급) |
| 짚어 줄 때 | 그 버튼 옆으로 가서 가리킨다. 사용자가 누르면 기뻐하고 물러난다 |

가리지 않기:

- 구석 자리는 하단 탭·대화 입력줄·‘신청하기’ 같은 **고정 막대의 높이를 재서 그 위** (`shared/lib/bottomBars`).
- 화면 맨 끝에 시작이 키만큼 빈 줄을 둔다(`--guide-lane`). 끝까지 내리면 마지막 버튼·말풍선이 시작이 밑에 깔리지 않는다.
- **자판이 올라오거나 지금 쓰는 입력칸과 겹치면 비켜 준다.**
- 누를 수 있는 것은 시작이 몸통 둘레뿐이다. 그림 둘레의 투명한 부분과 먼저 건네는 말풍선은 눌리지 않아 뒤 화면을 막지 않는다.
- 넓은 화면(태블릿·PC)에서는 본문 칸 바깥 빈 곳에 선다.
- 화면 설정 → **‘시작이 버튼’ 숨기기**. 숨겨도 도움말의 ‘시작이에게 물어보기’로 부를 수 있다.
- 긴급 도움(`/sos`)·운영자(`/admin`) 화면에는 두지 않는다 — 급한 순간에 잘못 누를 것을 만들지 않는다.

먼저 건네는 한마디는 조심스럽게: **화면마다 처음 한 번만**(기기에 기억), 들어온 지 1.2초 뒤에 나와 6.5초 뒤 접히고, 화면을 만지거나 내리면 바로 접힌다. 한마디가 없는 화면에서는 건네지 않는다 (`lib/screens.ts`의 `hint`).

### 2. 말풍선 — 화면을 덮지 않는다

- 아래에 붙는 말풍선. 뒤 화면을 어둡게 하지 않아 **묻고 있는 화면이 위에 그대로 보인다.** 넓은 화면에서는 오른쪽 아래에 뜬다.
- 말풍선도 고정 막대 위에 앉는다 — 열려 있어도 하단 메뉴·입력줄·‘신청하기’는 그대로 쓸 수 있고, 다른 화면으로 옮기면 접힌다.
- **한 번에 한 말만** 보여 준다. 스크롤해서 찾아야 하는 대화 기록이 없고, 앞의 답은 ‘앞의 말’로 다시 본다.
- 열면 "지금은 ‘○○’ 화면이에요. 뭘 도와드릴까요?"로 시작하고, **그 화면에 맞는 질문**을 고르게 한다. 첫 번째는 늘 "이 화면에서 뭘 해야 해요?".
- **‘말로 하기’**(브라우저 음성 인식)가 먼저, ‘글로 쓰기’를 누르면 입력칸이 나온다. 음성 인식이 안 되는 기기에서는 입력칸이 바로 보인다. 답마다 **‘소리로 듣기’**.
- ‘닫기’(글자가 있는 버튼) 또는 Esc. 닫으면 초점이 시작이에게 돌아간다.
- 아래에 늘 "미리 준비한 안내를 알려 드려요 · 급할 땐 119 전화". 입력 중인 척하는 연출은 없다 — 화면이 아직 불러오는 중이라 기다릴 때만 "화면을 살펴보고 있어요…"가 뜬다.
- 위로는 시작이가 설 자리를 늘 남긴다. 글씨가 커서 말이 길어지면 말풍선 안에서 스크롤한다.

### 3. 지금 화면을 기준으로 답하기

- 주소뿐 아니라 **화면 상태**도 본다: 인증번호 입력 단계인지, 받은 친구 신청이 있는지, 이미 신청한 활동인지, 자리가 다 찼는지, 차단된 대화인지, 위험 경고가 떠 있는지 (`lib/screens.ts`).
- 화면이 목록을 불러오는 중이면 잠깐(최대 2초) 기다렸다가 다 그려진 상태를 보고 답한다.
- 같은 말도 화면에 따라 달라진다: "신청 어떻게 해?" → 친구 화면에서는 친구 신청, 활동 화면에서는 활동 신청, 홈에서는 어느 쪽인지 되묻는다.
- "어디 있어?", "다시 말해 줘" 같은 되물음은 바로 앞의 답을 이어 받는다.

### 4. 짚어 주기 — 누르는 것은 사용자

- **‘어디 있어요?’** — 말풍선을 접고 그 버튼에 테두리를 두른 뒤, 시작이가 그 옆으로 가서 가리킨다. 화면을 덮지 않고, 테두리는 누름을 막지 않는다.
- **‘같이 가 보기’** — 여러 화면에 걸친 길을 한 걸음씩. 사용자가 짚은 곳을 누르면 다음 화면에서 다음 걸음을 짚는다 (예: ‘친구’ 메뉴 → ‘친구 신청’ 버튼).
- 시작이는 버튼 옆(자리가 없거나 하단 메뉴의 버튼이면 그 위)에 서고, 말풍선은 그 아래(자리가 없으면 위)에 뜬다 — 둘 다 그 버튼을 가리지 않는다. 큰 글씨로 말풍선이 길어지면 짚은 곳을 그만큼 더 위로 올린다.
- **대신 해 주지 않는다.** 엔진이 돌려줄 수 있는 동작은 짚어 주기·화면 이동·전화 걸기 화면 열기·화면 설정·되묻기 여섯 가지뿐이다 (`lib/types.ts`). 친구 신청·활동 신청·신고·차단·메시지 보내기·탈퇴는 어디 있는지만 알려 주고, 답에도 "직접 눌러 주세요"라고 적는다.
- 글자 크기·화면 대비는 예외로 **말풍선 안에서 사용자가 직접 고른다** — 자기 화면에만 영향을 주고 언제든 되돌릴 수 있고, 가입 전에는 설정 화면에 갈 수 없기 때문이다.
- 짚을 버튼이 화면에 없으면(이미 신청함, 목록이 빔) 다른 것을 가리키지 않고 "지금 화면에서는 보이지 않아요"라고 말한다.

### 5. 모르는 것은 모른다고

- 답은 전부 사람이 써 둔 문장이다 (`lib/topics.ts` 주제 42개, `lib/screens.ts` 화면 36개). 새 문장을 만들어 내지 않는다.
- 준비한 안내에 없으면: "그건 제가 준비한 안내에 없어요. 틀린 말을 지어내지 않으려고 모른다고 말씀드려요" + 지금 화면에서 물을 수 있는 것 + 도움말 + "가족이나 복지관 직원에게 화면을 보여 주고 물어보셔도 좋아요".
- 단서가 약하면 넘겨짚지 않고 "혹시 이 중에 있나요?"로 되묻는다.

### 6. 위험·긴급이 먼저

질문에 아래 표현이 있으면 길 안내를 하지 않고 **전화가 맨 앞**에 온다 (`lib/safety.ts`, 위에서부터 우선).

| 신호 | 답 |
|---|---|
| 죽고 싶다 등 위기 | 109 상담 전화(24시간) → 119 |
| 쓰러짐·숨·가슴 통증·화재·낙상 등 위급 | 119 → 112 (+ 로그인했으면 ‘긴급 도움’ 화면) |
| 강도·폭행·협박 등 범죄 | 112 → 119 |
| 돈·계좌·비밀번호·인증번호 요구 | 알려 주지 말 것 → 이미 보냈으면 112 → 대화 화면 ‘더보기’의 ‘신고하기’ 위치 |
| 몸 상태·약 (다른 주제로 못 알아들었을 때) | 답하지 않고 의사·약사, 급하면 119 |

정해 둔 표현만 알아듣기 때문에 돌려 말하면 놓칠 수 있다. 그래서 말풍선 아래에는 질문과 상관없이 **"급할 땐 119 전화"** 를 늘 둔다.

### 7. 시연이 실제처럼 보이지 않게

- 시작이 스스로: "저는 사람이 아니고, 미리 준비해 둔 안내를 찾아서 보여 드려요. 이 시연 화면에서는 AI나 상담원이 답하지 않아요."
- 시연 빌드(`VITE_DEMO=1`)에서만 답 아래 작은 글씨로 사실을 붙인다: 인증번호는 문자로 오지 않고 화면에 보인다 / 이웃은 자동으로 답한다 / ‘도움 요청’은 실제로 알림이 가지 않는다 / 신고는 실제 운영자에게 전달되지 않는다 / 말동무는 실제 AI가 아니다 / 복지시설·포인트·소식은 예시다. 일반 빌드에는 붙지 않는다.

### 8. 캐릭터 — 실시간 3D

- 원화의 몸·새싹·가방·볼터치를 3D로 옮겼다. 점토 인형 같은 반무광 재질에 따뜻한 조명, 원화의 굵은 외곽선은 뺐다.
- **그림이 아니라 기기에서 바로 그린다** (three.js, `lib/sijagi3d.ts`). 모델 하나의 팔·새싹·몸이 따로 움직이고, 표정은 얼굴 그림만 바꿔 끼운다. 가만히 있을 때도 숨 쉬고, 새싹이 흔들리고, 눈을 깜빡인다.
- 몸짓 5가지(기본·인사·기쁨·왼쪽 가리키기·오른쪽 가리키기) × 표정 4가지(웃음·기쁨·생각·걱정).
- 크기: 구석 84px, 말할 때 103px, 짚어 줄 때 96px (키 기준). 글자 크기 설정과 무관하게 같다.

가볍게, 그리고 못 그리는 기기를 위해:

| | |
|---|---|
| 늦게 받기 | 3D 코드는 앱 본체와 따로 묶여, 화면이 뜨고 1.5초 뒤 한가해졌을 때 받는다 — 3D 준비가 첫 화면의 내용이 그려지는 것을 막지 않게. 앱 본체는 3KB 늘었다 |
| 용량 (압축 전송 기준) | 3D 코드 142KB · 모델 약 290KB · 표정 5장 78KB. 한 번 받으면 서비스 워커가 저장한다 |
| 그 전·못 그릴 때 | 같은 구도의 정지 그림 8장(합쳐 44KB)을 보여 준다. 3D를 못 쓰는 기기, 그래픽 칩 없이 CPU로 그리는 기기(SwiftShader·llvmpipe 등 — 3D 준비에 화면이 몇 초 멈춘다)에서는 3D 코드를 아예 받지 않는다. 자동 테스트 브라우저도 여기에 든다 |
| 배터리 | 구석에서 쉴 때는 6초 뒤 그리기를 멈춘다. 말하거나 짚는 동안만 계속 그리고, 화면이 가려지면 멈춘다 |
| 움직임 줄이기 | 움직이지 않는다. 상태가 바뀔 때만 한 장 그리고, 자리도 미끄러지지 않고 바로 옮긴다 |

모델 다시 만들기: `frontend/scripts/sijagi/sculpt_rig.py` (numpy·opencv·scipy 필요) → `sijagi-rig.glb`와 `face-*.png`가 나온다. `src/features/guide/assets/`에 `sijagi.glb`, `face-*.png`로 넣는다. 색·잎 모양·이목구비 크기는 스크립트 위쪽 숫자로 바꾼다. 정지 그림(`still-*.webp`)은 같은 카메라로 따로 렌더해 넣은 것이라, 모양을 바꾸면 다시 뽑아야 한다.

### 9. 접근성

- 큰 글씨: 크기는 모두 토큰 기준. 글자 4단계 + 320px에서 가로 넘침 없음 (e2e).
- 선명한 화면: 테두리로 구분. 위급 답은 색뿐 아니라 굵은 테두리로도 다르게.
- 화면 낭독기: 말풍선은 `dialog`(모달 아님), 새 답은 `role="log"`로 올라오는 대로 읽힌다. 먼저 건네는 한마디와 짚어 줄 때의 말도 읽어 주고, 짚을 때는 초점을 그 버튼으로 옮긴다. 캐릭터 그림은 장식이라 읽지 않는다 (뜻은 늘 글자가 전한다).
- 터치: 누르는 것은 모두 56px(작은 것도 44px) 이상. 시작이의 누르는 자리는 약 67×87px.
- 움직임 줄이기: 시작이의 움직임·이동, 테두리 깜박임, 부드러운 스크롤을 모두 끈다.

| 질문 알아듣기 | 기기 안 규칙. 준비한 표현·말투만 (시험 80여 문장) | 사투리·오타·긴 사연·한 번에 여러 질문 |
| 답 내용 | 사람이 써 둔 문장 그대로 | 같은 검수 문서를 근거로 상황에 맞게 풀어 말하기 (근거 없으면 모른다고) |
| 지금 화면 알기 | 주소 + 화면에 보이는 몇 가지 상태 | 서버가 아는 내 상태: 포인트가 모자란 이유, 신청이 왜 막혔는지, 내 신청 내역 |
| 대화 이어 가기 | 바로 앞 답 하나 ("어디 있어?", "다시") | 여러 차례 주고받기, 지난번에 막혔던 곳 기억 |
| 짚어 주기·같이 가기 | 됨 (화면 안에서 동작) | 같음 — AI는 정해 둔 동작 목록에서 고르기만 한다 |
| 3D 시작이 | 됨 (기기에서 그린다, 서버 필요 없음) | 같음. 말하는 내용에 맞춘 입 모양·더 많은 몸짓은 따로 제작 필요 |
| 말로 묻기 | 브라우저 음성 인식. 지원 기기만, 인터넷 필요, 크롬은 음성을 구글로 보냄 | 서버 STT(C2): 어르신 발음·사투리, 모든 기기, 음성 보관 정책을 우리가 정함 |
| 소리로 듣기 | 브라우저 음성 합성 (기기마다 목소리 다름) | 서버 TTS(C2): 같은 목소리, 속도 조절 |
| 위험·긴급 알아채기 | 정해 둔 표현 + 늘 보이는 119 | 분류 모델로 돌려 말한 것까지, 보호자·복지사에게 실제 알림 |
| 사람에게 넘기기 | 없음 (가족·복지관 직원에게 보여 주라고 안내) | 고객센터·복지관 직원 연결 |
| 안내 고치기 | 코드 수정 + 배포 | 운영 화면에서 수정, 못 알아들은 질문 모아 보기 |
| 기록 | 남기지 않음 (탭을 닫으면 사라짐) | 동의를 받고 익명으로 — 어느 화면에서 무엇을 묻는지 |

### 실제 AI를 붙이는 자리

`lib/types.ts`의 `GuideEngine` 하나만 바꾼다. 화면(`components/`)은 그대로다.

```
frontend  features/guide/api/guideApi.ts   POST /guide/ask  { question, screen, variant, last_reply_id }
                                           → GuideReply (text · steps · actions · note)
backend   domains/guide (router → service) + integrations/llm
```

지켜야 할 것:

1. **위기·위급 판단은 AI보다 먼저, 기기에서.** `lib/safety.ts`는 서버 답을 기다리지 않고 지금처럼 바로 답한다. 네트워크가 끊겨도 119는 나온다.
2. **AI는 동작을 지어내지 못한다.** 돌려줄 수 있는 것은 `GuideAction`의 여섯 가지와 `lib/targets.ts`에 등록된 대상뿐. 화면이 모르는 대상·동작은 버린다. '대신 누르기'는 계약에 없다.
3. **근거는 검수한 문서뿐.** `topics.ts`·`screens.ts`를 근거 자료로 넘기고, 근거에 없으면 "모른다"가 기본.
4. **연결이 안 되면 지금의 기기 안 엔진으로** 돌아간다 (끊긴 채 기다리게 하지 않는다).
5. 실제 AI가 답하면 머리의 "미리 준비한 답" 문구를 "AI가 만든 답이라 틀릴 수 있어요"로 바꾼다.

## 구조

```
features/guide/
  lib/types.ts      엔진 ↔ 화면 계약 (GuideEngine, GuideReply, GuideAction)
  lib/engine.ts     답 고르기: 안전 → 주제 → 지금 화면 → 되물음 → 인사 → 몸 상태 → 모름
  lib/safety.ts     위기·위급·금전 요구·몸 상태
  lib/topics.ts     앱 사용법 주제 (단서 + 답)
  lib/screens.ts    화면별 안내 + 화면 상태 판별
  lib/targets.ts    짚을 수 있는 버튼·칸 (화면에 그려진 것을 링크·글자로 찾는다)
  lib/dom.ts        화면에서 실제로 찾기
  lib/sijagi3d.ts   실시간 3D 시작이 (three.js — 늦게 불러온다)
  assets/           모델(sijagi.glb) · 표정(face-*.png) · 대체용 정지 그림(still-*.webp)
  components/       Guide(흐름·설 자리) · SijagiActor(화면 위 캐릭터) · GuidePanel(말풍선) · Spotlight(짚어 주기)
```

- 다른 feature를 import하지 않는다. 짚을 대상은 화면에 그려진 링크·글자로 찾으므로, 화면 문구를 바꾸면 `targets.ts`·`screens.ts`도 같이 고친다 — 어긋나면 e2e가 알려 준다.
- 함께 고친 공용 코드: `shared/a11y/useA11yPrefs`를 앱 전체가 함께 보는 저장소로(말풍선에서 글자 크기를 바꾸면 설정 화면도 같이 바뀜), `shared/lib/bottomBars`(토스트와 공용), `app/AppLayout`(끝 여백).

## 한계 (숨기지 않기)

- 알아듣는 말은 준비한 표현까지다. 사투리·오타·긴 문장은 놓칠 수 있고, 그때는 되묻거나 모른다고 한다.
- 화면 속 요소를 글자로 찾으므로, 화면 문구를 바꾸고 안내를 안 고치면 "보이지 않아요"가 나온다.
- 말로 묻기는 기기·브라우저에 따라 버튼 자체가 안 보일 수 있다.
- 3D는 자동 시험 브라우저와 PC에서만 확인했다. 오래된 휴대폰에서 부드러운지, 배터리를 얼마나 쓰는지는 실제 기기에서 봐야 한다.
- 팔은 어깨에서 옆으로 드는 동작만 된다. ‘생각’은 표정만 바뀌고, 가리키기는 팔을 뻗는 정도다 (손가락이 없다).
- 모델은 삼각형 2만 2천 개로 줄였지만 압축은 더 할 수 있다 (meshopt 등은 아직 적용하지 않음).
- 실제 사용자 검증은 아직 하지 않았다. 문구는 화면과 대조했지만 어르신이 실제로 이해하는지는 A11에서 확인해야 한다.
