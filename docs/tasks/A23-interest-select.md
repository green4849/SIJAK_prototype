# A23. 가입 — 좋아하는 활동을 둥근 사진으로, 한 화면에 질문 하나

| 영역 | 크기 | 우선 | 상태 | 브랜치 |
|---|---|---|---|---|
| 폴리싱 | S | P1 | ✅ | `polish/A23-interest-select` |

> 전후 비교·폴리싱 참고: `docs/design/A23-interest-before-after.md` · 보고서용 요약: `docs/ux-changes.md` (2026-10-14)

## 왜
원래 시안(성향조사 — 취미)은 사진을 보고 여러 개 고르는 화면이었는데, 구현에서는 회색 테두리 글자 버튼 12개가 되어 딱딱하고 대충 만든 느낌이 났다.
또 가입 마무리 한 화면에 위치 동의와 좋아하는 것이 함께 있어 질문이 두 개 섞여 있었다.

## 바뀐 것 (사용자 관점)
- **두 단계로**: 1/2 "○○님, 어떤 활동을 좋아하시나요?" → 2/2 "사는 동네를 알려 주세요"(위치 정보 수집 동의, A21). 위쪽 '뒤로' 줄 오른쪽 막대로 지금 단계를 보여 준다. 2단계에서 '뒤로'를 누르면 1단계로 돌아가고 고른 것은 그대로.
- **둥근 사진 3열**: 활동마다 둥근 사진 + 이름. 고르면 사진 둘레 녹색 고리 + ✓ + 이름 초록. 사진을 못 불러오면 활동 아이콘 + 파스텔 바탕.
- **버튼은 늘 아래에**: 목록을 내려도 '다음'이 화면 아래에 붙어 있다. 고른 개수를 버튼 안에 작게("다음 2개 골랐어요"). 아무것도 안 골랐으면 버튼이 "하나 이상 골라 주세요"로 바뀌고 눌리지 않는다(오류창 대신).
- **5개 제한**: 넘기려 하면 버튼 바로 위에 이유를 알려 준다(기존 문구 그대로).
- **글씨**: 설명 문구 없이 제목 하나만(A18). 글자 '크게'·'아주 크게'에서는 2열, 넓은 화면(태블릿·PC)에서는 4열.

## 손댄 곳
- `shared/ui/PhotoChoiceGrid` — 둥근 사진 여러 개 고르기 (aria-pressed, 사진 실패 시 아이콘)
- `features/auth/components/interestChoices.ts` — 관심사 코드 → 사진·아이콘·색 한 곳에서 관리 (A20 `activityPhotos` 와 같은 방식, 바꿀 때 id만 교체)
- `SignupProfileForm` — 2단계, 하단 고정 버튼, 단계 막대 / `SignupPage` — 상단 바를 폼이 그림
- `shared/ui/TopBar` — `onBack` (페이지 이동 대신 이전 단계로)
- e2e `onboarding.spec.ts` — 두 단계 흐름, 뒤로 시 선택 유지, 안 골랐을 때 버튼 상태

## 이번에 하지 않은 것
- 마이페이지 → 프로필 수정의 '좋아하는 것'은 아직 글자 버튼 — 같은 `PhotoChoiceGrid` 로 맞출지 논의
- 사진 교체: 설명(alt) 기준으로 고른 Unsplash 사진이라 서양인 위주일 수 있음. 특히 여행(바닷가)·종교 활동(촛불)은 후보 비교를 충분히 못 함 → 화면 확인 후 교체 권장

## 완료 기준

- [x] typecheck·lint, e2e(onboarding)

## 진행 기록
- 처음엔 사진 카드(시안 그대로) + 시·도 선택 단계로 바로 구현했다가 되돌림 — 예전 main 기준이라 A21(위치 동의)과 어긋났고, 시안 비교 없이 코드부터 손댄 탓. A22처럼 **눌러 볼 수 있는 미리보기로 먼저 비교**하는 순서로 다시 진행
- 미리보기 세 안: A 사진 카드(시안 그대로) · B 사진 가득(사진 위 흰 글씨) · C 동그라미 3열 → **C 채택** (12개가 스크롤 조금으로 거의 다 보임)
- C의 약점(큰 글씨에서 이름이 두 줄로 잘게 끊김)은 큰 글씨 단계에서 2열로 바꿔 해결
- 작업 환경에서 사진 서버가 막혀 화면 캡처는 아이콘 대체 모습 — 실제 사진은 데모에서 확인
